# Lanto

Lanto is a multi-device remote operation tool for high-speed personal area networks. Windows handles local gaming and serves as the operation entry point, Linux1 runs the desktop, agent, and development tools, Mac provides native applications and build execution, and N100 serves as both a software router and NAS. The goal is to switch quickly between the local machine and remote desktops with one keyboard and mouse.

The current system includes an Electron + React + TypeScript control app with a UI and a headless Node.js + TypeScript Host. Device management, Host discovery and one time pairing, authentication status checks, authorization revocation, Moonlight launch, screen settings, and a shortcut to return to this machine are implemented. The first display target is 2560×1440, 30fps. Real remote streaming, input release, and switching latency still need to be verified on devices.

## Running the Controller

Requires Node.js 24.12 or a later 24.x LTS release, npm, and a separate installation of [Moonlight Qt](https://moonlight-stream.org/)。

```powershell
cd C:\Users\malou\Documents\GitHub\Lanto
npm ci
npm run dev
```

The first time Electron starts, it may download the corresponding runtime. To build and start the production version:

```powershell
npm run build
npm start
```

1. Select in Settings `Moonlight.exe`, or leave it blank to use automatic discovery.
2. Click Connect Host. You can first discover devices on the local network, then paste the one-time credentials generated by the controlled device to pair and add it. The Add Device option is also available for manually entering a Sunshine address directly.
3. Install and start Sunshine on the target machine, click Open Pairing Window, and complete streaming pairing in Moonlight. Once paired, close its settings window, then start the session from Lanto.
4. Click Open Remote Desktop. The screen appears in a separate native Moonlight window.
5. Use `Ctrl + Alt + F12` to return to this machine. You can change it in Settings; if the shortcut cannot be registered, starting a remote session will be blocked.

For quick everyday switching, use the native Windows `Alt + Tab`: Moonlight stays connected, so switching back does not require establishing the session again;`Ctrl + Alt + F12` closes the local streaming client. If mouse or display response feels slow, try 60fps and Prioritize Responsiveness in Settings. This mode disables Moonlight vertical synchronization and frame pacing waits, so screen tearing may occur. The frame rate is still set separately.

Performance Statistics can show Moonlight’s diagnostic overlay and save that client run’s log under `media-logs/`, created only when statistics are enabled. Logs may contain host addresses, device information, and app information, and are not included in Git. The next connection will not create a diagnostic log if statistics are turned off. Moonlight’s own `Ctrl + Alt + Shift + S` can temporarily show or hide the statistics overlay.[Meaning of Statistics Fields](https://github.com/moonlight-stream/moonlight-docs/wiki/Frequently-Asked-Questions#what-do-the-numbers-mean-in-the-on-screen-connection-statistics)。

Windows can use the experimental Shared Device and Texture graphics pipeline. A short local comparison measured average rendering time dropping from the default 0.19–0.21ms to 0.07–0.08ms; decoding has not yet shown a consistent win. The default remains Automatic. Some drivers and VRR still need separate testing. Evidence, rewrite boundaries, and retest tools are in[Performance Investigation](docs/performance-investigation.md)。

Device addresses are blank by default; the interface does not pretend that a device is online. Paired Hosts use an authenticated endpoint to check identity and Sunshine status; manual devices only check whether TCP 47989 is reachable. Neither means that video is connected. Custom Sunshine ports are not yet supported.

This version manages one streaming process at a time. Switching to another device first closes the current client, then starts the next one; multi-device prewarming and embedded displays are not yet implemented. Returning to the local machine attempts to close the window normally, then terminates the client process created by Lanto if it times out. It does not send the remote application termination `quit` command. Moonlight’s own `Ctrl + Alt + Shift + Q`can be used as an emergency backup exit shortcut; it still needs verification in actual systems and games.

Configuration is saved in Electron’s `userData` directory, usually `%APPDATA%\Lanto\config.json`. The actual path can be viewed in Settings. Host tokens are encrypted by the system secure storage and written to `trusted-hosts.json`in the same directory; they are not returned to the interface. Moonlight still manages its own streaming certificates. If configuration is corrupted, the original file is retained and an error is shown; it is not silently reset.

## Headless Host

The controlled device requires Node.js 24.12 or a later 24.x release; the Host itself does not load Electron or React. First obtain the repository source on the controlled device and enter the project directory:

```bash
npm ci --omit=dev
npm run host -- init --name Linux1 --address 192.168.1.20
npm run host -- start
```

Replace the example address with the actual private-network IP of the controlled device. Open another terminal in the same directory to generate pairing credentials:

```bash
npm run host -- pair
```

Paste the entire credential string from the output that begins with `LANTO1.` into the controller. It expires after five minutes and becomes invalid after use; generating a new one replaces the previous credential. If LAN multicast is unavailable, you can also connect directly using the credentials. By default, data is saved in the controlled device’s user directory `~/.lanto/host`. Use `--data-dir` to specify another local directory for all commands.

```bash
npm run host -- status
npm run host -- controllers
npm run host -- revoke <Controller UUID>
```

The Host listens on TCP 48199 by default and uses mDNS UDP 5353 for discovery; it does not automatically adjust the system firewall. Local CLI management operations use only the loopback address. Host and Sunshine are separate processes; Sunshine currently needs to be installed and started independently. See[Host Usage](docs/host.md)。

## Development and Checks

```powershell
npm run typecheck
npm run host:build
npm run format:check
npm test
npm run test:smoke
```

Core tests cover configuration, sessions, real TLS, pairing invalidation, authorization revocation, the Host CLI, and local process cleanup. UI smoke tests use a loopback Host, isolated configuration, and an off-screen Electron window, covering device operations, Host pairing, system encryption storage, restart recovery, and unpairing. Screenshots are written to the ignored `test-results/`. Tests do not connect to real remote machines or modify everyday user configuration. Installers, a unified media installation wizard, and automatic updates have not yet been added.

## Preliminary Selections

Electron + React + TypeScript has been selected for the controller, with electron-vite for the build. The priority is to verify a Sunshine Host and the native Moonlight client. The Lanto controller manages devices, shortcuts, and the media worker process; the first version keeps the media process independent. Moonlight currently has a single active session structure, so the multi-machine hot-switching process isolation approach will be verified first.

Selkies is the main comparison for the browser integration approach, but the takeover boundaries of the existing Wayland desktop affect computer use on Linux1. RustDesk is the full remote-control comparison. Program execution on Mac uses SSH, and Peekaboo Bridge is the first choice for verifying UI operations. Credentials reuse KRU; form autofill on the Mac side will be verified separately end to end.

## Constraints Already Set

- Connect directly over the local network first, without relying on public internet accounts, cloud relays, or public port forwarding.
- Local Windows games display directly; switching back to the local machine must release all remote input capture.
- The Linux desktop operated by the agent and the desktop seen by the user must be the same session.
- The main source working directory is stored on the N100 NAS, and Linux1 mounts it to perform development tasks; build caches and dependencies may use Linux1’s local temporary storage.
- N100 is known to have 8GB of memory and 6 2.5G Ethernet ports; the disk interfaces, network cards for other devices, GPU, and desktop environment still need to be inventoried on site.
- Rust, Electron, JS, TS, Python, and Godot are the main development technologies. Build tasks requiring Windows-only toolchains can be handled by a Windows virtual machine on Linux1.
- The current repository remains private; no third-party implementation source code was copied or introduced, and a distribution license for the project itself has not yet been selected.
